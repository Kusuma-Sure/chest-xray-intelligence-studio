# CheXpert Capstone — Four-Model Chest X-ray Intelligence Studio

A local research application for multi-label classification of CheXpert chest X-ray images. It includes a FastAPI backend, responsive browser frontend, one shared training pipeline and four selectable architectures: **ViT-B/16, DenseNet121, CapsNet and GAT**.

> **Important:** no trained CheXpert checkpoint or dataset is bundled. The dashboard and API can be launched before training, but prediction for a model remains disabled until its real checkpoint exists. This is deliberate: the application never invents predictions, heatmaps or benchmark metrics.

## 1. Windows installation (Python 3.10 recommended)

Open CMD inside the project folder.

```cmd
py -3.10 -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
```

Install PyTorch and Torchvision as a compatible pair. For CPU-only Windows:

```cmd
pip install torch torchvision
```

Then install the rest:

```cmd
pip install -r requirements.txt
```

You can also run `setup_windows.bat` from CMD to execute the setup interactively. A CUDA GPU is optional for the web application; CPU training is possible but substantially slower. For GPU installation use the command recommended by the official PyTorch selector for the installed driver/CUDA combination.

## 2. Start the dashboard

From the project root with `.venv` activated:

```cmd
python -m uvicorn backend.api:app --host 127.0.0.1 --port 8000
```

Or double-click `run_windows.bat` after setup.

Open:
- Dashboard: <http://127.0.0.1:8000>
- API documentation: <http://127.0.0.1:8000/docs>
- Health status: <http://127.0.0.1:8000/api/health>

Keep the CMD window open while using the dashboard. `Ctrl+C` stops the server.

## 3. Train the models in Google Colab

The supplied notebook is `docs/CheXpert_Capstone_Training_Colab.ipynb`. It expects a ZIP with a top-level folder named `chexpert_capstone`, matching this project's folder. Zip the **project folder** so Colab extracts `/content/chexpert_capstone/backend/train.py`.

In Colab:
1. Select a GPU runtime (Runtime → Change runtime type → T4 GPU, where available).
2. Open the supplied notebook.
3. Upload `chexpert_capstone.zip` when prompted.
4. Allow KaggleHub to download `ashery/chexpert`; configure Kaggle access if required.
5. Select one model in `MODEL_NAME`: `vit`, `densenet`, `capsnet`, or `gat`.
6. Start with the notebook's small subset settings to verify the pipeline, then increase training/validation samples and epochs.
7. Check the saved `.pt` checkpoint and matching metrics files in Google Drive.
8. Repeat the notebook training run for each of the other models you want to enable.

The notebook installs `pandas`, `scikit-learn`, `pillow`, `opencv-python-headless`, `networkx`, `tqdm` and `kagglehub`. Colab supplies PyTorch/Torchvision in its standard runtime.

### Training command (when running locally with the dataset)

```cmd
python -m backend.train --model densenet --data-root "D:\datasets\CheXpert-v1.0-small" --epochs 3 --batch-size 8 --max-train-samples 5000 --max-valid-samples 1000
```

Choose `vit`, `densenet`, `capsnet`, or `gat`. Use `--max-train-samples 0 --max-valid-samples 0` for all CSV rows. `--no-pretrained` skips ImageNet initialization downloads. The training script saves the best checkpoint and validation metrics/history in `checkpoints/` by default, or in `--output-dir` when supplied.

## 4. Install trained checkpoints locally

The shared training pipeline writes:

```text
checkpoints/
├── vit.pt
├── densenet.pt
├── capsnet.pt
└── gat.pt
```

Copy the `.pt` files and matching `*_summary.json` / `*_metrics.csv` files generated by this project into your local `checkpoints/` folder. If you trained to Google Drive, download them from `MyDrive/chexpert_capstone/checkpoints/`.

**Previously trained DenseNet/CapsNet models:** this API also checks for the raw state-dictionary filenames saved by your earlier notebooks: `best_densenet121_chexpert.pth`, `best_capsnet_10epoch.pth`, `best_capsnet_weighted.pth`, and `best_capsnet_chexpert.pth`. Copy those files directly into `checkpoints/`. The loader checks parameter shapes strictly before enabling predictions. Existing DenseNet121/CapsNet files may be compatible because those model definitions and preprocessing were matched to the supplied notebooks; if strict loading reports a mismatch, train them with the included unified notebook. The older Hugging Face ViT folder is not compatible with this TorchVision ViT implementation; train ViT with the unified notebook. GAT must be trained with this project pipeline.

After copying, stop and restart the FastAPI process. Run:

```cmd
python scripts\check_models.py
```

A model becomes selectable in the dashboard only when its checkpoint file exists. The API verifies checkpoint metadata, label order and parameter shapes when loading it. A mismatched checkpoint returns an error; another architecture is never silently substituted.

### Compatibility note

This code's ViT is TorchVision `vit_b_16`. It is not binary-compatible with the Hugging Face ViT checkpoint (`google/vit-base-patch16-224`) saved by the earlier standalone notebook. Train ViT using this project's unified Colab notebook for a `vit.pt` checkpoint. Older DenseNet121/CapsNet state-dictionary checkpoints are accepted under their original filenames when their parameter shapes match; the API performs strict loading and reports a clear error otherwise. GAT is a new implementation following the uploaded GAT design notes and must be trained with this project pipeline.

## 5. Dataset and label policy

Expected dataset layout:

```text
CheXpert-v1.0-small/
├── train.csv
├── valid.csv
├── train/patient.../*.jpg
└── valid/patient.../*.jpg
```

CSV files must contain `Path` and all 13 finding columns in `backend/config.py`. The baseline conversion is `-1 → 0`, `NaN → 0`, `1 → 1`, following the provided baseline notes. This is a simplifying experiment policy, not a claim that uncertain or unmentioned labels are clinically negative.

ViT/DenseNet/GAT use grayscale radiographs expanded to 3 channels, resized to 224×224 and ImageNet-normalized. CapsNet uses grayscale 224×224 tensors in `[0,1]`, matching the supplied CapsNet notebook preprocessing.

## 6. API

- `GET /api/health` — runtime/device and number of checkpoint files.
- `GET /api/models` — all architecture availability states.
- `GET /api/benchmarks` — actual metrics generated by the training pipeline; absent measurements stay blank.
- `POST /api/predict?model=densenet&threshold=0.5&explain=true` — multipart image inference.
- `GET /docs` — interactive API documentation.

Prediction returns 13 sigmoid probabilities, labels above the selected threshold, processing time, supported attribution output and graph structure. The threshold is not a calibrated clinical cut-off.

## 7. Explainability and GraphRAG scope

- DenseNet121: Grad-CAM from `features.denseblock4`.
- CapsNet: gradient-based activation map from `conv3`.
- ViT-B/16: gradient × activation over final-block patch tokens.
- GAT: learned attention aggregation over the model's 7×7 spatial graph.

The graph retriever creates image → classifier → predicted finding → coarse region-category relations. `docs/medical_evidence.json` is empty by default. It returns source evidence only after you add verified, referenced source records. No medical citations or LLM-generated clinical explanations are fabricated. Coarse region labels are structural tags, not localization claims.

## 8. Benchmarks

Training writes per-finding AUROC/AUPRC and threshold-based accuracy/precision/recall/F1, plus a summary JSON. The comparison tab reads only these generated files. No default benchmark figures are seeded. For a rigorous model ranking, evaluate all four checkpoints on the same patient-disjoint holdout set with identical label policy and preprocessing.

## 9. Verification

```cmd
python -m compileall backend tests
python -m pytest -q
```

Architecture smoke tests use random initialization to check tensor shapes only; they are not model performance evaluation. The inference API never uses those test weights.

## Safety and research limitations

This is an academic research prototype, not a medical device. A high probability is not a confirmed diagnosis. Do not use it for diagnosis, triage or treatment decisions.
